# Requirements

This directory contains authoritative project requirements.

Requirements are produced through human↔Claude Grill-style discovery before implementation. They should contain the information Codex needs to execute goals without requiring routine clarification.

Capture, as appropriate:

- project goals and user-visible outcomes;
- functional requirements;
- non-functional requirements;
- constraints;
- non-goals;
- acceptance expectations;
- integration boundaries;
- operational or compatibility requirements;
- known assumptions and unresolved questions.

Do not force information into a fixed schema when prose is clearer. The objective is unambiguous engineering intent, not template compliance.

Material architectural choices that require an explicit decision belong in ADRs, with links from requirements/design where useful.
